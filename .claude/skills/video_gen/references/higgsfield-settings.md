# Higgsfield 세팅 매트릭스

2단계(시안)와 3단계(최종본)에서 읽는다. 모델 스펙은 바뀌므로, 값을 확정하기 전에
`higgsfield model get <model_id>`로 현재 스키마를 한 번 확인한다.

## 실행 경로 두 가지

**CLI** (`higgsfield generate create ... --wait`) — 파일 경로를 그대로 넘기면 자동 업로드된다.
`--wait`를 붙여 한 번에 끝낸다.

**MCP** (`mcp__Higgsfield__generate_video` 등) — CLI 인증이 안 될 때 쓴다. 원격 세션에서는
브라우저 OAuth 콜백이 로컬 포트로 돌아와야 해서 `higgsfield auth login`을 완료할 수 없다.
이 경우 MCP가 유일한 경로다.

먼저 `higgsfield account status`로 확인하고, 실패하면 MCP로 전환한다. 둘 다 막히면
사용자에게 로컬 터미널 로그인을 요청한다.

## 모델 선택

### 핵심 갈림길: Seedance 2.0 vs 2.5

이름 때문에 2.5가 상위 버전으로 보이지만 **서로 다른 도구다.**

| | Seedance 2.0 (`seedance_2_0`) | Seedance 2.5 (`seedance_2_5`) |
|---|---|---|
| 최대 해상도 | **4K** | **1080p** (상한) |
| 길이 | 4–15s | **4–30s** |
| 레퍼런스 | `image`, `start_image`, `end_image`, `video`, `audio` | 이미지·비디오·오디오 **배열** |
| 모드 | 단일 | `t2v` / `omni_reference` / `video_edit` / `video_extension` |
| 강점 | 고해상도, 멀티샷, 모션 | **레퍼런스 기반 일관성**, 편집·연장 |

**제품 고정이 최우선인 이 워크플로에서는 2.5의 `omni_reference`가 구조적으로 유리하다.**
레퍼런스를 배열로 제대로 받기 때문이다. **Higgsfield의 `seedance_2_5`는 1080p까지 직접 뽑고
길이도 30초까지 받으므로, SNS·상세페이지 납품(1080p)이면 업스케일 없이 한 번에 끝난다.**

`upscale_video`가 필요한 경우는 **4K 납품뿐이다.** 그때만 총액을 비교해서 사용자에게 보여주고
고르게 한다:

```
경로 A: seedance_2_0 @ 4K                      → 비용 X
경로 B: seedance_2_5 @ 1080p + upscale_video   → 비용 Y + Z
```

`higgsfield generate cost` 로 실제 값을 뽑아 비교한다. 앞선 사례에서 다른 플랫폼 기준
"저해상도 생성 + 업스케일"이 직접 고해상도 생성보다 **비쌌던** 적이 있으므로, 추측하지 말고
매번 실측한다.

### 대안 모델

| 상황 | 모델 |
|---|---|
| 모션이 단순하고 더 싸게 | `kling3_0` (start/end frame만 받음 — 레퍼런스 배열 없음) |
| 시네마급 최고 품질 | `cinema_studio_video_3_0` |
| 빠른 대량 드래프트 | `veo3_1_lite` |
| 광고 포맷 (UGC·언박싱·TV스팟) | `marketing_studio_video` |
| 이미지 최대 7장 레퍼런스 | `gemini_omni` |

⚠️ 단일 레퍼런스만 받는 모델(`grok_video_v15`, `veo3`, `veo3_1`, `kling3_0_turbo`,
`kling2_6`)은 이 워크플로에 **쓰지 않는다.** 레퍼런스를 여러 장 넣을 수 없어 제품 고정이 불가능하다.

## 단계별 프리셋

### 2단계 — 8초 시안

목적이 무드 확인이므로 해상도를 낮춘다. 대신 레퍼런스는 전부 넣는다.

```
모델      : seedance_2_5 (omni_reference) — 레퍼런스 일관성 확인이 목적이므로
해상도    : 720p 권장 (480p도 가능하나 9:16 세로에서는 컬러 블로킹 판독이 어렵다)
길이      : 8s
비율      : 최종본과 동일 (바꾸면 구도가 달라져 참고가 안 됨)
레퍼런스  : 받은 전량 (제품컷 + 착용샷 모두)
```

시안에서 **판단할 수 있는 것**: 컬러 그레이딩, 카메라 무브, 강아지 움직임, 전체 무드,
컬러 블로킹의 대략적 위치.

시안에서 **판단할 수 없는 것**: 로고 판독, 미세 봉제선, 원단 질감, 부자재 광택.
해상도 때문이지 프롬프트 문제가 아니다. 이걸 사용자에게 미리 알려야 불필요한 재작업을 막는다.

### 3단계 — 최종본 (확정 기본값)

**이 값들은 사용자가 확정한 브랜드 기본 세팅이다. 사용자가 명시적으로 바꾸라고 하기 전까지
그대로 쓴다.**

```
모델      : seedance_2_5 (omni_reference)
해상도    : 1080p
길이      : 20초
샷 수     : 6샷
사운드    : 끔 (generate_audio: false) — 영상만 생성한다
레퍼런스  : 받은 전량, 역할별 배분 (product-lock.md 참고)
비율      : 채널에 맞춰 결정 (릴스·틱톡·쇼츠 9:16 / 웹 히어로·유튜브 16:9)
```

비용은 **180크레딧** (9크레딧/초 × 20초). 1080p 요금은 길이에 완전 비례하므로 길이를 줄여
아끼는 것 말고 다른 절약 수단은 없다.

**샷 구성이 이 단계의 핵심 작업이다.** 6개 샷은 서로 다른 구도·카메라 무브·속도를 가져야 하고,
그 조합으로 제품이 효과적으로 보여야 한다. 기법 선택과 20초 6샷 기본 골격은
`references/camera-techniques.md`에 있다 — 최종본 프롬프트를 쓰기 전에 반드시 읽는다.

`generate_audio: false`를 빠뜨리지 않는다. 기본값이 `true`라 명시하지 않으면 오디오가 붙는다.
프롬프트의 AUDIO 블록은 그대로 두는데, 모델이 화면 리듬을 잡는 데 계속 쓰이기 때문이다.

**비율은 기본값으로 고정하지 않는다.** 채널에 따라 구도가 통째로 달라지므로 기획서 단계에서
용도를 확인하고 정한다. 시안과 최종본의 비율은 반드시 같아야 한다.

## 실측 비용 (`seedance_2_5`, `omni_reference`, 9:16)

2026-08-25에 `generate_video`의 `get_cost`로 실측한 값. 모델 가격은 바뀌므로 확정 전에 다시 잰다.

| 길이 | 해상도 | 크레딧 |
|---|---|---|
| 8s | 480p | 20 |
| 8s | 720p | 52 |
| 12s | 1080p | 108 |

12초 1080p 최종본이 108크레딧이라, 720p 시안(52)을 한 번 거치고 가도 총액이 160크레딧 선이다.
시안을 아끼는 것보다 최종본을 한 번에 맞추는 게 싸다.

## CLI 사용 예

```bash
# 비용 먼저
higgsfield generate cost seedance_2_5 --duration 8 --resolution 720p

# 시안
higgsfield generate create seedance_2_5 \
  --prompt "$(cat prompt.txt)" \
  --image ./front.jpg --image ./back.jpg \
  --image ./worn_a.jpg --image ./worn_b.jpg \
  --duration 8 --aspect_ratio 9:16 --resolution 720p \
  --wait

# 스키마 확인
higgsfield model get seedance_2_5
```

`--image`를 반복해서 여러 장을 넘긴다. 모델이 단일 레퍼런스만 받으면 CLI가 제출 전에
로컬에서 막아준다.

## 프롬프트 길이에 대한 주의

Higgsfield의 일반 프롬프트 가이드는 "~200 토큰 이하"를 권한다. 하지만 그건 카탈로그
전체에 대한 범용 조언이고, **Seedance 계열은 블록 구조의 긴 프롬프트를 처리한다**
(다른 게이트웨이에서 이 모델의 프롬프트 상한이 10,000자로 보고된 사례가 있다).

seedance-clean의 블록 구조를 유지하되, 제출 후 결과가 프롬프트 뒷부분을 무시한 것처럼
보이면 그때 압축한다. 줄이는 순서는 **월드빌딩·환경 묘사부터**이고,
**ACTIVE REFERENCES와 POSITIVE LOCKS는 깎지 않는다** — 그게 제품을 지키는 부분이다.

확실히 하려면 `higgsfield model get <model>`로 프롬프트 상한을 확인한다.

## 생성 후 반드시 확인할 것

**레퍼런스가 실제로 붙었는지 결과 메타데이터에서 확인한다.** 넣은 장수와 결과에 기록된
레퍼런스 수가 같아야 한다. 0장이면 프롬프트가 아무리 정교해도 제품은 맞지 않는다 —
이건 프롬프트를 고칠 문제가 아니라 인자를 고칠 문제다.

작업이 큐 직후 실패하면 프롬프트가 아니라 레퍼런스 파라미터 형식을 먼저 의심한다.
실패한 작업은 대개 과금되지 않으므로, 재시도 전에 잔액을 확인하면 확실해진다.

본 생성 전에 최저가 설정(가장 싼 모델 / 최저 해상도 / 최단 길이)으로 **레퍼런스 첨부만
검증하는 테스트**를 한 번 돌리면, 긴 생성을 날리는 일을 막을 수 있다.
