# video_gen — 제품 화보 동영상 3단계 워크플로

제품컷 여러 장과 착용샷, 설명 한 단락을 받아, 제품이 한 프레임도 변형되지 않는 브랜드 화보 영상을 만든다.

## 이 워크플로가 지키는 단 하나의 원칙

의류·하네스 화보 영상에서 실패는 거의 항상 같은 방식으로 온다. 영상은 예쁘게 나왔는데 **제품이 그
제품이 아니다.** 컬러 블로킹이 좌우로 뒤집히고, 지퍼가 사라지고, 로고 탭이 반대쪽 가슴으로 옮겨가고,
퀼팅 패턴이 다른 무늬가 된다. 브랜드 입장에서 이건 "조금 아쉬운 영상"이 아니라 **쓸 수 없는 영상**이다.

그래서 이 워크플로의 모든 단계는 제품 고정을 중심으로 설계돼 있다. 레퍼런스를 역할별로 쪼개 넣고,
레퍼런스에 이미 보이는 디테일도 프롬프트에 말로 다시 적고, 결과를 원본과 대조한다. 기획이 화려한
것보다 제품이 정확한 게 우선이다. 둘 중 하나를 포기해야 하면 기획을 깎는다.

## 입력

사용자가 주는 것:

| 항목 | 내용 | 역할 |
|---|---|---|
| 제품컷 2~4장 | 앞면 / 뒷면 / 측면 (있으면 디테일컷) | **제품 마스터** — 컬러 배치, 부자재·로고 위치 |
| 착용샷 2장 | 강아지가 입은 모습, 각도 다르게 | 착용 핏 + 반려견 identity + 씬 무드 |
| 설명 | 제품명, 소재, 컬러명, 기능, 타깃 | 카피·무드·씬 설계의 근거 |

장수는 유연하게 받되 **어느 장이 제품 마스터인지는 반드시 확정한다.** 보통 부자재와 로고가 가장
선명한 앞면 컷이다. 이걸 모르면 제품 고정이 처음부터 어긋난다. 각도가 겹치는 컷만 있으면
(예: 앞면 두 장) 그 사실을 짚고 빠진 각도를 요청한다 — 후면 레퍼런스가 없으면 뒷모습 샷에서
드리프트가 난다.

**이미지 전달 방법:** Higgsfield CLI와 MCP 모두 채팅 첨부를 읽지 못한다. 로컬 파일 경로를 받거나
(CLI가 자동 업로드), 사용자가 Higgsfield에 먼저 올린 뒤 업로드 ID를 받는다. 원격 세션이라 파일
시스템에 없다면 그 사실을 먼저 알리고 경로/ID를 요청한다 — 레퍼런스 없이 진행하면 이 스킬의 목적이
사라진다.

## 1단계 — 영상 기획서

**seedance-clean 스킬을 먼저 호출한다.** 프롬프트 블록 구조·FOV 표·타임코드 문법이 거기 있고,
그걸 거치지 않고 쓴 프롬프트는 카메라 값이 무시되거나 컷이 제멋대로 들어간다.

기획서는 사용자가 **읽고 고르는 문서**다. 내가 정해서 통보하는 게 아니라, 추천안을 제시하되 대안을
같이 보여줘서 사용자가 최종 결정하게 한다. 각 항목마다 "왜 이걸 추천하는지"를 한 줄로 붙인다 —
근거 없는 추천은 사용자가 판단할 수가 없다.

기획서 구성과 세팅 선택지 표는 `references/planning-doc-template.md`에 있다. 그대로 채워서 쓴다.

기획서에 반드시 들어가는 것:

1. **제품 분석** — 제품컷에서 읽어낸 고정 대상 목록. 컬러 배치(위치까지), 실루엣·기장, 봉제선·패턴,
   부자재(지퍼·버클·D링) 위치와 색, 로고·라벨 위치와 형태, 스트랩 경로와 폭.
2. **컨셉과 스토리 아크** — 제품 설명에서 끌어낸 한 문장 컨셉 + 시작·전환·마무리.
3. **세팅 결정표** — 길이 / 비율 / 컬러 그레이딩 / 슬로우모션 / 카메라 무브 / 탑뷰 등.
   **각 항목마다 추천안에 ✅ 표시하고 대안을 2~3개 함께 제시한다.**
   그레이딩 기본값은 `references/style-presets.md`의 브랜드 기본 프리셋(2000년대 35mm 필름룩)이다.
   이 프리셋은 미세 디테일을 부드럽게 만들므로, 용도가 상세페이지면 그 트레이드오프를 먼저 짚는다.
4. **샷 리스트** — 타임코드별 샷 크기, FOV(도), 카메라 무브, 속도(실시간/슬로우), 액션.
5. **PRODUCT LOCK** — 제품 고정 문구. `references/product-lock.md`의 패턴을 제품에 맞게 채운다.
6. **Seedance 프롬프트** — seedance-clean 블록 구조로 작성한 영어 프롬프트, 코드블록 하나에.
7. **비용 견적** — 시안과 최종본 각각. 실제 값은 `higgsfield generate cost`로 확인해 적는다.

기획서를 낸 뒤에는 **멈춘다.** 사용자가 세팅을 확정하기 전에 생성으로 넘어가지 않는다.

## 2단계 — 8초 시안

목적은 완성본이 아니라 **무드 확인**이다. 컬러 그레이딩이 의도대로 나오는지, 카메라 무브가 제품을
잘 보여주는지, 강아지 움직임이 자연스러운지 — 이 셋만 보면 된다. 그래서 짧고 싸게 뽑는다.

시안에서 확인하는 것과 확인하지 않는 것을 사용자에게 명확히 알린다. 시안은 해상도를 낮춰 뽑으므로
**로고 판독이나 미세한 봉제선은 시안에서 판단할 수 없다.** 이걸 미리 말하지 않으면 사용자가 시안을
보고 "로고가 뭉개졌다"고 판단해 불필요하게 재작업하게 된다.

세팅:

- 기획서 전체 샷 리스트가 아니라 **가장 대표적인 구간 한 덩어리**만 8초로 자른다.
  보통 제품이 가장 잘 보이는 샷 + 그 앞뒤 호흡.
- 모델·해상도는 `references/higgsfield-settings.md`의 시안 프리셋을 따른다.
- 레퍼런스는 시안에서도 **전부** 넣는다. 여기서 빼면 무드 확인 자체가 의미가 없다.
- 비율은 최종본과 동일하게 간다. 비율이 바뀌면 구도가 바뀌어서 시안이 참고가 안 된다.

제출할 때 함께 전달할 것: 결과 링크, 사용한 세팅, 소모 크레딧, 그리고 **"이 시안에서 봐주셔야 할
것"** 체크리스트.

여기서도 **멈춘다.** 시안 승인 전에 최종본으로 가지 않는다.

---

## 3단계 — 최종본

시안 피드백을 프롬프트에 반영한 뒤 한 번에 뽑는다.

### 확정 기본값 — 사용자가 바꾸라고 하기 전까지 그대로 쓴다

| 항목 | 값 |
|---|---|
| 모델 | `seedance_2_5` (`omni_reference`) |
| 해상도 | 1080p |
| 길이 | 20초 |
| 샷 수 | 6샷 |
| 사운드 | **끔** (`generate_audio: false`) — 영상만 생성 |
| 비용 | 180크레딧 |

비율은 기본값이 없다. 채널에 따라 구도가 달라지므로 기획서 단계에서 용도를 확인해 정하고,
시안과 최종본을 같은 비율로 맞춘다.

### 이 단계에서 실제로 하는 일은 샷 구성이다

세팅이 고정됐으므로 판단할 게 하나 남는다 — **6개 샷을 어떻게 짤 것인가.** 목표는 두 가지이고
둘 다 만족해야 한다:

1. **시청자가 지루하지 않을 것.** 6개 샷이 서로 다른 구도·카메라 무브·속도를 가져야 한다.
   카메라 높이를 위아래로 흔들고, 슬로우는 히어로 액션 한 구간에만 건다.
2. **제품이 효과적으로 보일 것.** 샷을 다 짠 뒤 제품 분석 표의 고정 대상을 하나씩 짚으며
   "이건 몇 번 샷에서 보이는가"를 답해본다. 답이 없는 항목이 있으면 샷을 바꾼다.

기법 카드와 20초 6샷 기본 골격은 `references/camera-techniques.md`에 있다.
**최종본 프롬프트를 쓰기 전에 반드시 읽는다.** 기법을 감으로 고르면 측면 트래킹만 여섯 개
나오고, 그러면 정면 D링과 등 지퍼는 영상에 한 번도 안 나온다.

최종본 제출 시 **반드시 제품 대조 검토를 붙인다.** 링크만 던지지 않는다:

- 컬러 배치가 앞/뒤 제품컷과 같은 위치인가
- 지퍼·버클·D링이 같은 자리, 같은 색인가
- 로고·라벨 탭이 같은 쪽 가슴, 같은 크기인가
- 봉제선·퀼팅 패턴이 같은 무늬인가
- 스트랩 경로와 폭이 같은가

영상을 직접 볼 수 없는 환경이면 **그 사실을 숨기지 말고 밝히고**, 위 항목을 사용자가 확인할
체크리스트로 넘긴다. 확인하지 않은 것을 확인한 것처럼 말하면 브랜드가 잘못된 영상을 내보내게 된다.

## 로고를 다루는 방식

Seedance 계열은 생성된 글자를 뭉갠다. 이건 프롬프트로 해결되지 않는다. 그래서 로고는
**위치와 형태(작은 라벨 탭, 자수 패치)로만 고정**하고, 글자가 판독되어야 하는 용도라면
클로즈업 인서트 구간을 잡아두고 **후반 합성**으로 처리하도록 기획서에 명시한다.

프롬프트에 "the logo reads PUPPIA" 같은 문장을 쓰지 않는다. 모델이 글자를 그리려다 오히려
이상한 문자를 만든다.

## 실패했을 때 먼저 볼 것

- **레퍼런스가 실제로 붙었는가.** 결과 메타데이터에서 레퍼런스 항목 수가 넣은 장수와 같은지 본다.
  0장이면 프롬프트가 아무리 좋아도 제품은 안 맞는다.
- **작업이 큐 직후 죽었는가.** 보통 레퍼런스 파라미터 형식 문제다. 프롬프트가 아니라 인자를 본다.
- **실패한 작업은 대개 과금되지 않는다.** 재시도 전에 잔액을 확인하면 확실해진다.
- 프롬프트에 `@image1` 같은 태그를 쓰지 않는다. Higgsfield/Seedance 레퍼런스에는 태그를 특정
  이미지에 연결하는 기제가 없어서 리터럴 텍스트로 남고, 모델이 화면에 글자로 그리려 든다.
  "all attached reference images show the same garment"처럼 **묶어서 지칭**한다.

## 인증이 막혀 있을 때

`higgsfield account status`가 실패하면 CLI 로그인이 필요하다. 다만 원격·비대화형 세션에서는
브라우저 OAuth 콜백이 로컬 포트로 돌아오기 때문에 **로그인을 완료할 수 없다.** 이 경우
Higgsfield MCP 도구(`generate_video` 등)가 연결돼 있으면 그쪽으로 진행하고, 둘 다 막혀 있으면
사용자에게 로컬 터미널에서 `higgsfield auth login`을 실행해 달라고 요청한다.

## 참고 파일

- `references/planning-doc-template.md` — 기획서 템플릿과 세팅 선택지 표. 1단계에서 읽는다.
- `references/style-presets.md` — 브랜드 기본 그레이딩(35mm 필름룩)과 대안 프리셋. 1단계에서 읽는다.
- `references/product-lock.md` — 제품 고정 문구 패턴 라이브러리. 프롬프트 작성 시 읽는다.
- `references/higgsfield-settings.md` — 모델·해상도·비용 매트릭스와 CLI 사용법. 2·3단계에서 읽는다.
- `references/camera-techniques.md` — 촬영기법 카드와 20초 6샷 골격. **3단계에서 반드시 읽는다.**
